# UltraCMD × Raycast — Full Audit & Remediation Plan

Ground truth: all 48 files in `raycast-manual/`. App: ~12.3k lines Swift under `Sources/ultracmd/`. The good news: the shell fundamentals are already right — `OverlayLauncherWindow` is an `NSPanel` with `.nonactivatingPanel` + `canJoinAllSpaces`, keyboard flows through an `NSEvent.addLocalMonitorForEvents(.keyDown)` router before SwiftUI, and a ⌘K action panel exists. The audit below lists every gap found; the phases after it are ordered by user-reported pain.

---

## PART 1 — AUDIT

### A. User-reported bugs (all root causes confirmed at source)

1. **Backspace closes the launcher.** `AppModel.swift:1665-1669`: at root with empty query, backspace calls `hideLauncher()`. Since `prepareForDisplay()` (AppModel.swift:135-139) resets `query = ""` on every summon, one stray backspace right after opening always dismisses. Raycast: backspace-on-empty *navigates back*; at root it's a no-op.
2. **Quit is broken three ways.** (a) Status-menu Quit greyed out: `AppDelegate.swift:62` — `for item in menu.items { item.target = self }` assigns the AppDelegate as target of the Quit item whose action is `NSApplication.terminate(_:)`; the delegate doesn't implement that selector so NSMenu auto-validation disables it. (b) ⌘Q does nothing anywhere: the app never builds `NSApp.mainMenu`, so no key equivalents exist. (c) ⌘W does nothing for the same reason.
3. **Clipboard "Enter to paste" only copies.** `AppModel.swift:782-809`: paste writes the pasteboard, hides the panel, waits a fixed 180 ms, then posts a synthesized ⌘V via CGEvent — but only if `AXIsProcessTrusted()`; otherwise it silently degrades to "Copied — press ⌘V" (exactly the behavior reported — the AX grant is missing or stale from re-signing). Even when trusted, 180 ms may fire before the target app regains keyboard focus.
4. **"system settings" ranking is inverted.** `AppIndexer.swift:127` gives all 33 settings panes the keywords `["settings","preferences","system",title]`. Query "system" exact-matches the keyword (raw ≈123.6 × 0.7 keyword weight ≈ 86.5) for 33 panes + 4 system commands (`CommandRegistry.swift:121-146` also carry "system"), while the System Settings *app* only gets a title prefix match ≈ 62.9 — buried under ~37 rows. Root cause: no IDF-style demotion of keywords shared by every item, and panes have no parent-app relationship. Bonus bug: About and Storage panes share one URL → duplicate item ids `"settings:x-apple.systempreferences:com.apple.SystemProfiler.AboutExtension"` (AppIndexer.swift:95,97).
5. **Clipboard layout inverted.** `ClipboardView.swift:17-31`: list = `maxWidth: .infinity` (takes ~500pt), detail = fixed 252 pt right column. User wants the opposite: compact left list sidebar, wide right detail with content (text/image) on top and metadata below.

### B. Keyboard/UX gaps vs Raycast manual

- Backspace-on-empty only navigates back in emojiPage; should also pop clipboard/aiChat/extensionView (Raycast 02-Search-Bar).
- Missing: ⌘↑/⌘↓ section jumps, ⌥↑/⌥↓ page jumps, Ctrl+N/P, ⌘Esc pop-to-root, ↑/↓ at list ends cycling search history (05-Keyboard-Shortcuts).
- No show/hide animation at all (`hide()` = bare `orderOut`, LauncherWindow.swift:169-174) — feels abrupt vs Raycast's fade.
- Window level is `.floating`; spec (and Raycast) sit above the menu bar — should be `.mainMenu + 1` (~statusBar level) (LauncherWindow.swift:36).
- Empty-query state shows usage recents + all apps A-Z; Raycast shows a **Favorites** section (⌘F to pin) — favorites concept absent app-wide.
- Fallback results ("Ask AI", "Search the Web") are hardcoded (AppModel.swift:219-242); Raycast makes fallbacks user-configurable and ranked.
- No root-search sensitivity setting, no compact window mode (collapse to search bar when empty), no search-history reset, no "Reset Ranking" action.
- Emoji are excluded from root search (separate page only); Raycast surfaces emoji inline.

### C. Wireframe/layout consistency (the "3 universal primitives" rule)

| Surface | Pattern today | Violations |
|---|---|---|
| Root list | List | Good, but 46/50/54 pt rows only scale **up**; no compact preset |
| Clipboard | Split | Detail pane inverted (bug A5); rows use `minHeight` instead of fixed like root |
| Extensions | List/Detail/Form hybrid | Custom 30 pt header, fixed 40 pt rows, 13.5 pt titles, 10 pt section headers, `.primary` icon tint, **no footer pills** — five deviations from root chrome (ExtensionView.swift:38-66, 115-120, 219-258) |
| Emoji | Grid | A 4th pattern; fine as a formalized primitive, but metrics (56 pt cells, 8.5 pt captions) don't share Theme tokens |
| Settings | Native macOS `NavigationSplitView`+`Form` | Completely different design language (deliberate, SettingsView.swift:4-10) — flagged for later glass redesign |
| AI Chat | Two implementations | In-panel Quick AI vs 940×680 HUD window share some components but differ in paddings/metrics |

Also: section headers 10.5 pt (root/clipboard) vs 10 pt (extensions); row titles 14/14.5/15 vs 13 (clipboard) vs 13.5 (extensions); GlassMenu rows are 32 pt vs 46 pt list rows. Compaction targets: search bar 58→52, font 21→19, row default 46→40 (with a new "Compact" density as default baseline), footer pills 34→30, window 540→~460 tall (content-driven with max), extension rows unified to shared row primitive.

### D. Liquid-glass design deviations

- Real `glassEffect` only on macOS 26; elsewhere `ultraThinMaterial` fallback (ListChrome.swift:73-99) — fine, but `Theme.hudTint` charcoal at up to 0.92 opacity (Theme.swift:24-27) mutes the vibrancy into a flat matte; reduce overlay so material reads as glass.
- Settings + Chat windows: HUD chat has glass; Settings has none.
- Consistent (keep): 0.5 pt hairline border, 9-slice maskImage corners, no shadows on materials, hidden scroll indicators with edge fades.

### E. Search engine & indexing mistakes

- **All ranking runs synchronously on the main thread** every keystroke (`@MainActor` `query.didSet → refreshResults`, AppModel.swift:163-179) — violates the "UI thread never blocks" rule; fine for 200 apps, will stutter as extensions/panes grow.
- **Index scan runs synchronously at launch** (`SearchEngine.init → rebuildIndex()`, SearchEngine.swift:12-19) — directory scans on the critical path.
- **No file watching** — newly installed apps are invisible until manual re-index/relaunch.
- **No IDF on keywords** — generic shared keywords ("settings", "system") exact-match for +60 × weight; this is bug A4's engine-level cause.
- Usage boost (max +48, UsageStore.swift:35-41) is healthy Raycast-style frecency; keep, but duplicate pane ids pollute it (A4).
- Spotlight file results (max 6, score −1000) arrive late and ungrouped (AppModel.swift:346-364) — should render as a distinct "Files" section.
- Emoji/URL detection/color conversion absent from root search (Raycast has all three inline).
- No persistent store for anything except usage JSON + clipboard JSON — acceptable for the app index (cheap rebuild), but clipboard history stores **full text inline in the JSON index** (ClipboardHistory.swift:400-418) → index bloat; violates the compaction rule (long strings should be payload-truncated).

### F. Clipboard subsystem

- Polling `Timer` at 0.35 s on main RunLoop (ClipboardHistory.swift:305-313) — works, but capture-to-persist path can be moved off-main; Raycast v2 uses direct detection.
- Capacity pruning (default 500, pinned preserved) exists; missing: token-limit truncation of long payloads, time-decay pruning, "update history after action" setting, paste-sequentially, bulk delete by time window, OCR.
- Paste pipeline fragility covered in A3.

### G. Lifecycle/misc

- No `applicationSupportsSecureRestorableState` (console warnings on macOS 12.2+).
- No `NSApp.mainMenu` — also disables ⌘W/⌘Q/⌘, inside the real Settings/Chat windows.

## PART 2 — IMPLEMENTATION PLAN

### Phase 1 — P0 fixes (user-reported)

1. **Backspace** (`AppModel.handleKeyDown` case 51): root+empty → return `false` (no-op, let TextField handle it); add navigate-back for clipboard/aiChat/extensionView when query empty; keep emojiPage pop. File: AppModel.swift:1665-1674.
2. **Quit**: in `setupStatusBar` (AppDelegate.swift:51-64) stop blanket-assigning `item.target`; leave Quit's target nil (or `NSApp.shared`) so `terminate(_:)` validates. Add ⌘W (hide launcher) + ⌘Q (terminate) to `handleKeyDown`/`performKeyEquivalent` router. Build a minimal programmatic `NSApp.mainMenu` (App menu: Settings/Hide/Quit; Window menu: Close/Minimize) so standard equivalents work in Settings/Chat windows too. Implement `applicationSupportsSecureRestorableState → true`.
3. **Robust paste**: replace fixed 180 ms with a poll (≤600 ms, 30 ms ticks) that waits until the panel is no longer key window before posting ⌘V, single retry. Surface AX state: clipboard footer shows "⏎ Paste to <App>" only when trusted; otherwise a "Grant Accessibility…" pill that opens System Settings → Privacy & Accessibility and re-checks. Add Accessibility status row (trusted/not + button) to Settings → General.
4. **Ranking fix**: remove `"system"` from pane keywords (AppIndexer.swift:127); add IDF-style demotion in `FuzzySearch.matchAny`/`SearchEngine` — a keyword's exact/prefix bonus scales down by how many items share it; give the System Settings app subtitle/keywords parity; fix the duplicate About/Storage id (Storage gets its own extension URL). Add `CoreTests` ranking cases: "system", "system settings", "settings", "wifi" → app or correct pane on top respectively.

### Phase 2 — Clipboard split-view redesign (user spec)

Flip `ClipboardView`: fixed ~240 pt left sidebar (compact 32-36 pt rows: type icon, one-line preview, relative time, pin dot) + flexible right detail: large content preview first (scrollable monospaced text, full-width image, color swatch, file list), metadata block below (source app, kind, size/dimensions, copy count, copied-at), footer hint bar ("⏎ Paste to <App> · ⌘↵ Copy · ⌥↵ Plain"). Keep sections (Pinned/Today/…) and ⌘P filter. Store long text payloads in per-entry files (or truncated in index) to stop JSON bloat — first step of the compaction rule.

### Phase 3 — Compactness + wireframe consistency

- Rebaseline `Theme` metrics: row 40 (default) / 46 / 52, row title 13.5/14/15, search bar 52, search font 19, footer pills 30, unified 10 pt section headers, window height ~460 (content-driven, max 560).
- Extract shared primitives into `ListChrome`: `ListRow`, `SectionHeader`, `SplitLayout`, `FormChrome`, `GridChrome`; refactor RootView, ClipboardView, ExtensionView, EmojiView onto them. ExtensionView adopts the shared floating-search-bar chrome + footer pills.
- Add show/hide fade+scale (0.13 s easeOut) in LauncherWindow show/hide; bump level to `.mainMenu + 1`; reduce hudTint overlay opacity range so vibrancy reads as glass.

### Phase 4 — Search engine & indexing hardening (architecture rules)

- Move full ranking off-main: serial `ultracmd.search` queue + generation counter; instant app-prefix pass on main for zero-latency, async full pass publishes a snapshot back to the `@MainActor` (progressive refinement, Raycast-style).
- Launch: build SearchEngine with empty index, rebuild on background queue, publish when ready. Add app-install watching (NSWorkspace notifications + directory FSEvents debounced 2 s) re-scanning off-main.
- Group Spotlight results under a "Files" section header.

### Phase 5 — Deferred (documented, later passes)

Settings glass redesign; Favorites + per-command aliases/hotkeys; Quicklinks; Snippets; calculator units/colors/URL detection; system toggles (Wi-Fi/BT/DND/volume); emoji inline in root search; compact window mode; configurable fallbacks + sensitivity; paste-sequentially; bulk clipboard delete; OCR. Each maps to the manual pages cited in the audit.

### Verification

- `swift build && swift test` after each phase; new ranking + key-routing unit tests in Phase 1.
- Manual checklist: summon → backspace does nothing; ⌘Q quits; ⌘W hides; status-menu Quit clickable; type "system" / "system settings" → System Settings app is result #1; clipboard Enter pastes into a real frontmost app (with and without AX grant — degraded path shows the Grant pill); clipboard layout = narrow list left, wide detail right; visual density pass on all five surfaces; drag/snap and guide overlays still work.
